## 1. 核心原则

### 1.1 单一事实来源 (Single Source of Truth)

- **代码实现是第一事实**：如果文档与代码不一致，以代码为准。
- **架构事实聚合**：架构相关的全局事实（层定义、边界约束、术语表）应聚合到一份核心文档（如 `FACTS.md`），其他架构文档（如旧版 `ARCHITECTURE_REFERENCE.md`、`整体逻辑.md`）重定向指向该文档，避免多份文档描述同一组事实。

### 1.2 变更即更新

- **不单独维护文档**：代码修改必须伴随对应文档更新。没有文档同步的代码修改视为不完整。
- **最小同步范围**：只修改受变更影响的文档，不无差别地刷新全部文档。

### 1.3 精确引用

- 所有文档引用使用相对路径，确保在版本控制（Git）下链接有效。
- 尽量锚定到文档中的具体章节（使用 Markdown 锚点 `#章节名`）。

## 2. 文档分类体系

项目文档分为以下六大类，每一类有独立的维护规则：

| 分类 | 说明 | 维护触发条件 | 示例 |
|------|------|-------------|------|
| **架构事实** | 全局架构事实、层定义、边界约束、术语表 | 架构决策、层依赖变化、术语新增/修改 | `FACTS.md` |
| **类职责** | 每个 Java 类型一份同名文档 | 新增/删除/修改 Java 类、方法签名变化 | `docs/类职责/Ae2StorageAnalyzer.md` |
| **参考指南** | 命令参考、API 参考、开发指南、契约文档 | 命令接口变化、API 变化、JSON 字段变化 | `COMMANDS_REFERENCE.md` |
| **AI 协作文档** | AI 入口、审查清单、重构指南、前端 prompt | 开发流程变化、审查标准变化、前端契约变化 | `AI_ENTRY.md` |
| **计划/路线图** | 阶段计划、下一步方向 | 阶段推进、新方向确定 | `下一步计划.md` |
| **重定向文档** | 已迁移内容的导航入口 | 内容迁移时创建/更新 | `ARCHITECTURE_REFERENCE.md`（重定向版） |

### 2.1 重定向文档规范

当文档内容迁移到新位置时，原位置应保留重定向文档，包含：

```
# 原文档名（重定向说明）

> ⚠️ **本文档已迁移**。内容已合并到 [`目标文档`](目标文档.md)。

## 迁移说明

| 原内容 | 新位置 |
|--------|--------|
| 内容块 A | [`目标文档` §章节名](目标文档.md#章节锚点) |
| 内容块 B | [`目标文档` §章节名](目标文档.md#章节锚点) |

## 快速导航

- [目标文档 — 章节名](目标文档.md#章节锚点)

> **最后更新**: YYYY-MM-DD
```

## 3. 文档格式规范

### 3.1 通用格式要求

- **首行标题**：使用 `# 文档名`。
- **最后更新标记**：文档末尾或顶部标注 `> **最后更新**: YYYY-MM-DD`。
- **使用清晰的层级结构**：`##` 为一级章节，`###` 为二级小节，避免超过四级。
- **表格统一**：同一类文档使用统一的表格格式。

### 3.2 类职责文档格式

每个 Java 类型对应一份 `.md` 文件，路径与 Java 包路径一致。格式如下：

```markdown
# 类名

| 维度 | 说明 |
|------|------|
| **包路径** | `包路径/类名.java`（不含 `src/main/java/` 前缀） |
| **定位** | 一句话说明该类在系统中的定位 |
| **职责** | 详细描述职责边界，列举或概括关键行为 |
| **关键方法** | `方法签名(参数类型)` → `返回类型` |
| **依赖** | 直接依赖的外部类/接口 |
| **被谁使用** | 直接使用本类的类/服务 |
| **边界** | 明确声明"不做什么"以划定职责边界 |

## 维护备注
- 职责变化时更新本表。
- 关键方法签名变化时同步更新。

> **最后更新**: YYYY-MM-DD
```

### 3.3 架构事实文档格式

使用原子化事实编号（如 `FACT-001`），每个事实一句话。事实可被其他文档精确引用。

### 3.4 检查清单格式

使用 Markdown 任务列表 `- [ ]` 表示检查项，按章节分组。

## 4. 交叉引用规则

### 4.1 语法

所有文档间引用使用 Markdown 相对路径链接，格式统一：

```markdown
[显示文本](相对路径.md)
```

带章节锚点时：

```markdown
[显示文本](相对路径.md#章节名)
```

### 4.2 引用要求

| 场景 | 引用方式 | 示例 |
|------|---------|------|
| 同一目录下的文档 | `[类职责索引](类职责/索引.md)` | `[整体逻辑](整体逻辑.md)` |
| 子目录引用父目录 | `[架构参考](../ARCHITECTURE_REFERENCE.md)` | `[类职责总览](../类职责总览.md)` |
| 父目录引用子目录 | `[Ae2StorageAnalyzer](类职责/ae2/analysis/Ae2StorageAnalyzer.md)` | `[索引](类职责/索引.md)` |
| 引用具体章节 | 追加 `#章节名` | `[术语表](架构/FACTS.md#6-术语表精简版仅核心术语中英文对照--一句话定义)` |
| 引用代码中的方法 | 标注行号 | `SorterMoveOperation.execute()` in [`SorterMoveOperation.java`](src/main/java/.../SorterMoveOperation.java:142) |

### 4.3 引用完整性

- 新增文档后，检查是否有其他文档需要引用它并更新。
- 文档内容迁移后，原位置必须保留重定向文档。
- 定期检查（或每次修改时附带检查）所有相对路径链接是否有效。

## 5. 术语一致性

### 5.1 术语表维护

- 术语表应集中在单一文档中（如 `FACTS.md` 的术语表章节），其他文档引用该处。
- 每个术语包含：**术语名称**、**中英文对照**、**一句话定义**。

### 5.2 术语使用规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 禁止自创别名 | 使用术语表定义的名称，不发明同义不同名的术语 | 用 "Zone" 而非 "存储分区" 的随意混用 |
| 能力线术语隔离 | 不同能力路径使用各自语义的术语 | `merge` 路径中不使用 `zone`/`route` 术语 |
| 跨文档一致性 | 同一术语在所有文档中含义一致 | "DAV" 在所有文档中指 DigitalAssetVault |
| 首次出现标注 | 术语首次出现时标注英文原名 | "数字资产库 (DigitalAssetVault, DAV)" |

### 5.3 术语变更流程

1. 更新术语表文档。
2. 全文搜索，更新所有使用了该术语的其他文档。
3. 如有中英文对照变化，同步更新所有使用旧术语的引用。

## 6. 变更驱动同步机制

### 6.1 修改类型 → 需同步文档映射表

| 修改类型 | 必须同步的文档 | 检查项 |
|---------|--------------|--------|
| 新增/删除 Java 类 | `docs/类职责/` 下对应文档 + `docs/类职责/索引.md` | 索引统计数更新、分层统计更新 |
| 修改类职责/方法签名 | 对应 `docs/类职责/` 文档 | 关键方法、职责描述更新 |
| 修改架构边界/层依赖 | `docs/架构/FACTS.md` | 相关 FACT 更新、层约束更新 |
| 修改命令接口 | `docs/参考/COMMANDS_REFERENCE.md`（或等价的命令参考文档） | 命令名、参数、语义更新 |
| 修改 API 契约 | `docs/参考/API_REFERENCE.md`（或等价的 API 参考文档） | 方法签名、返回值更新 |
| 修改 JSON 字段 | `docs/日志与JSON字段契约.md` + 前端 prompt（如有前端消费方） | 字段名、类型、可选性、向后兼容性 |
| 修改网络包 | `docs/类职责/network/` 下对应文档 | 序列化/反序列化逻辑更新 |
| 修改 GUI/方块 | `docs/类职责/block/` + `docs/类职责/client/screen/` 对应文档 | 按钮功能、布局变化 |
| 修改测试 | 测试指南文档（如新增测试模式或框架） | 新测试模式的说明 |
| 文档内容迁移 | 原位置创建重定向文档 + 目标位置更新 | 重定向表完整、导航链接有效 |

### 6.2 同步流程

```
代码/配置修改完成
    ↓
[开发者] 分析修改范围 → 判断受影响文档（参考上表）
    ↓
[开发者] 逐一更新受影响文档
    ↓
[开发者] 验证：交叉引用完整性、术语一致性、格式合规
    ↓
（可选）[审查者] 执行文档同步检查（参考 §8）
```

### 6.3 例外情况

以下情况可跳过文档同步（但需在提交信息或审查时说明原因）：

- 纯注释/格式化修改，不影响行为。
- 仅修改构建配置（如 `build.gradle`、`gradle.properties`）。
- 仅修改元配置文件（如 `.gitignore`、`.roomodes`）。
- 仅修改测试数据或测试资源文件（不涉及测试框架变化）。

## 7. 版本与日期管理

### 7.1 最后更新标记

- 每份文档顶部或底部标注 `> **最后更新**: YYYY-MM-DD`。
- 同步更新时同时更新日期。
- 仅修改格式/错别字时不强制更新日期（但推荐更新）。

### 7.2 文档版本与代码版本的关系

- 文档不独立维护版本号。
- 文档的"版本"通过 Git commit 历史追溯，与对应代码变更的 commit 绑定。

## 8. 审核检查清单

文档维护完成后的自检清单：

### 8.1 格式检查

- [ ] 文档标题使用 `#` 一级标题
- [ ] 章节层次不超过四级
- [ ] 表格格式统一（同类文档用相同列结构）
- [ ] 最后更新日期已标注且正确

### 8.2 交叉引用检查

- [ ] 所有 `[](相对路径.md)` 链接目标存在
- [ ] 带锚点的链接指向正确的章节
- [ ] 新增/删除文档后更新了索引文档
- [ ] 没有死链接（链接到已删除但未重定向的文档）

### 8.3 术语检查

- [ ] 所有术语与术语表一致
- [ ] 能力线术语未混淆（merge 路径无 zone/route 术语等）
- [ ] 首次出现的术语标注了英文原名

### 8.4 变更覆盖检查

- [ ] 所有受修改影响的文档已更新
- [ ] 新增 Java 类有对应的职责文档
- [ ] 索引文档的统计数字已更新
- [ ] 架构事实文档（如 FACTS.md）已反映最新决策

## 9. 常见反模式

| 反模式 | 表现 | 纠正 |
|--------|------|------|
| 文档滞后 | 代码改了，文档没改 | 建立"不更新文档不改代码"的习惯 |
| 事实分散 | 同一组架构事实分布在多个文档中 | 合并到单一核心文档，其余位置重定向 |
| 链接失效 | 文档路径变化后未更新引用 | 移动文件后全文搜索引用并更新 |
| 术语膨胀 | 同一概念有多个不同名称 | 统一到术语表，淘汰旧名称 |
| 过度重定向 | 内容频繁迁移导致多层重定向 | 减少迁移次数，一次迁移到位 |
| 格式不一致 | 同类文档使用不同排版 | 定义统一的文档模板并遵守 |
| 索引不同步 | 新增/删除文档后未更新索引 | 索引更新纳入变更检查清单 |
| 幻想式文档 | 为未实现的未来功能编写详细文档 | 只文档化已实现或正在实现的内容 |
