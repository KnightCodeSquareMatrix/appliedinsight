## 优先级说明

| 符号 | 含义 | 说明 |
|------|------|------|
| 🔴 P0 | 必须做 | 不做则发布后不可玩 | 缺少资源导致崩溃 / 没有配方 / 无法合成 |

## 🔴 P0 — 必须做

### P0-1: SorterCommandBlock 缺失资源资产

> **问题**：`SorterCommandBlock` 的 blockstate、model、texture 完全缺失，游戏中会显示为紫黑方块。

| # | 文件路径 | 期望产出 | 验证方式 |
|---|---------|---------|---------|
| 1 | `src/main/resources/assets/appliedstoragesorter/blockstates/sorter_command_block.json` | blockstate JSON，引用 block model | `./gradlew build` 无资源警告；游戏中放置不显示紫黑 |
| 2 | `src/main/resources/assets/appliedstoragesorter/models/block/sorter_command_block.json` | block model JSON（可借用现有纹理或新增） | 同上 |
| 3 | `src/main/resources/assets/appliedstoragesorter/models/item/sorter_command_block.json` | item model JSON，引用 block model | 游戏中背包图标正常显示 |
| 4 | `src/main/resources/assets/appliedstoragesorter/textures/item/sorter_command_block.png` | 方块纹理 PNG（16×16 或 32×32） | 游戏中纹理正确渲染 |

**参考**：现有 [`digital_asset_vault` blockstate](src/main/resources/assets/appliedstoragesorter/blockstates/digital_asset_vault.json) 和 [block model](src/main/resources/assets/appliedstoragesorter/models/block/digital_asset_vault.json) 可作模板。

### P0-4: META-INF 模板展开验证

> **问题**：`neoforge.mods.toml` 是 Gradle 模板文件，需验证占位符替换正确。

| # | 操作 | 期望产出 | 验证方式 |
|---|------|---------|---------|
| 1 | 执行 `./gradlew generateModMetadata` | 生成 `build/tmp/.cache/expandedMetadata/neoforge.mods.toml` | 检查占位符 `${mod_id}`、`${mod_version}`、`${loader_version_range}`、`${neo_version}`、`${minecraft_version_range}`、`${ae2_version_range}` 均已被实际值替换 |
| 2 | 检查生成的 TOML 无残留占位符 | 无 `${...}` 残留 | `grep '\${' build/tmp/.cache/expandedMetadata/neoforge.mods.toml` 返回空 |

**参考**：[模板文件](src/main/templates/META-INF/neoforge.mods.toml)。

## 🟡 P1 — 强烈建议

### P1-1: 核心路径测试覆盖

> **问题**：当前仅 4 个测试文件，核心搬运/规划/引擎路径缺少单元测试。

| # | 测试类（建议） | 测试内容 | 验证方式 |
|---|--------------|---------|---------|
| 1 | `RoutingEngineTest` | 规则引擎：正常匹配、优先级排序、continueOnMatch 链、fallback 兜底、REJECT/ONLY_MARK 行为 | `./gradlew test --tests "*RoutingEngineTest"` 绿色 |
| 2 | `SorterMoveOperationTest` | 搬运操作：extract/insert/rollback 事务、电量计算、结果聚合 | 同上 |
| 3 | `MergeMovePlannerTest` | merge 规划器：同类物品识别、容量约束、目标 cell 选择 | 同上 |
| 4 | `Ae2ZoneMoveExecutorTest` | Zone 执行器：正常搬运、部分失败回滚、跨 zone 搬运 | 同上 |
| 5 | `EnergyCostCalculatorTest` | 电量计算：各项系数贡献、边界值（0 距离、0 物品数） | 同上 |
| 6 | `SorterDumpAnalyzerTest` | 离线分析器：dump 解析、健康标志检测、语义节点候选识别 | 同上 |
| 7 | `RuntimeZoneRegistryBuilderTest` | Zone Registry 构建：DAV zone 解析、外部存储处理、未分配 cell 归属 | 同上 |

**参考**：[测试指南](docs/参考/TESTING_GUIDE.md) 中的编写规范。

## 执行顺序建议

建议按以下批次依次推进，批次之间可并行：

### 第 1 批（P0 → 游戏可发布）

```
P0-1  →  SorterCommandBlock 资源资产（缺失则紫黑崩溃）
P0-4  →  META-INF 模板验证（缺失则模组加载失败）
         → 以上两项完成后，确认模组可正常加载、方块可放置
P0-2  →  DAV 配方
P0-3  →  SorterCommandBlock 配方
         → 以上两项完成后，确认所有物品可在生存模式获得
```

### 第 2 批（P0 → 玩家可理解）

```
P0-5  →  lang 文件补齐（命令反馈 + GUI 文本 + 错误消息）
         → 完成后，全命令路径的玩家反馈均为本地化文本
```

### 第 3 批（P1 → 质量保障）

```
P1-1  →  核心路径测试（RoutingEngine → SorterMoveOperation → MergeMovePlanner）
P1-3  →  SorterCommandBlock GUI 纹理确认
P1-4  →  GUI 本地化验证
         → 至少 P1-1 完成后才可打 release tag
```

### 第 4 批（P1 → 文档收口）

```
P1-2  →  文档一致性检查（FACTS.md 同步、类职责同步、重定向验证）
         → 可在上述批次并行执行
```

### 第 5 批（P2/P3 → 未来规划）

```
P2-1/P2-2 → 纹理美化（发布后迭代）
P3-1～P3-6 → 明确推迟到 v2.0
```
