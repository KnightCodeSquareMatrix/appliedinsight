# Applied Energistics: Insight 项目总结（细化到类）

> 能力拆分文档：
> - `docs/自动整理/自动合并同类-sorter.md`
> - `docs/存储管理/过滤器-zone-router-存储管理.md`

## 1. 项目定位

Applied Energistics: Insight 当前主要分成三条能力线：

1. **AE2 内部存储自动整理**
   - 扫描 AE2 / ExtendedAE 的 drive 与 cell
   - 找出同类物品分散在多个 cell 的情况
   - 尝试把同类物品归并到更合适的目标 cell

2. **基于规则的物品路由与离线分析**
   - 定义 zone / filter / route / profile
   - 对 dump 文件进行离线分析
   - 输出 routing analysis / suggestion / generated draft profile
   - 为未来前端（React Query Builder）提供 schema 与 metadata 契约

3. **自定义治理型物理设备**
   - 提供 sorter 自己的 item / block / block entity / menu / screen
   - 把“治理语义”从纯逻辑模型推进到真实设备本体
   - 当前第一步是 `数字资产管理卡 + 数字资产库（DAV）`

当前项目同时包含：

- Minecraft / NeoForge 运行时入口
- AE2 网络扫描与 dump 导出
- 纯 Java 路由规则模型
- 纯 Java 离线分析链路
- profile 自动草案生成器
- 面向未来 zone 注册的第一批物理设备骨架

## 3. 根包：模组入口与配置

### `appliedinsight`
**职责：** 模组主入口。

**主要功能：**
- 通过 `@Mod` 声明模组
- 注册 common setup 生命周期监听
- 注册服务端配置 `Config.SPEC`
- 在 NeoForge 事件总线上注册 `SorterCommands`

**定位：** 整个 mod 的启动装配点。

### `appliedinsightClient`
**职责：** 客户端入口。

**主要功能：**
- 仅在客户端分发环境下加载
- 注册配置界面工厂 `IConfigScreenFactory`

**定位：** 客户端配置 UI 接入点。

### `Config`
**职责：** 集中定义 mod 配置项。

**主要功能：**
- `ENABLE_SORTER`：总开关
- `SCAN_INTERVAL_TICKS`：扫描间隔
- `MAX_TRANSFERS_PER_OPERATION`：单次整理最多执行的移动步数
- `VERBOSE_LOGGING`：是否输出详细日志
- `SPEC`：最终提供给 NeoForge 注册的配置规范

**定位：** 运行期行为的基础开关与阈值来源。

## 4. 应用服务层

这一层是最近新增的结构，目标是把“命令响应”和“实际执行”拆分开。

### `SorterMeService`
**职责：** 承接 `/sorter me` 的实际业务执行流程。

**当前状态：**
- 目前仍接第一版“自动合并同类”路径
- 后续会逐步接入：
  - `MESorter`
  - `ZoneSorter`
  - zone 分发 executor
- 运行时将支持直接读取玩家指定的 Minecraft 实例内 profile JSON

**主要功能：**
- 检查 `ENABLE_SORTER` 是否开启
- 检查命令执行者是否为玩家
- 调用 `Ae2ControllerTargetResolver` 解析当前主网
- 调用 `Ae2DriveScanner` 扫描 drive 状态
- 调用 `SorterMovePlanner` 生成整理计划
- 执行 `SorterMoveOperation`
- 调用 `SorterFileLogger` 记录失败、计划和执行结果
- 返回 `SorterMeCommandResult`

**定位：** `/sorter me` 的应用层服务，供命令层与未来其他入口复用。

### `SorterDumpService`
**职责：** 承接 `/sorter me dump` 的实际业务执行流程。

**主要功能：**
- 检查 `ENABLE_SORTER` 是否开启
- 检查命令执行者是否为玩家
- 调用 `Ae2ControllerTargetResolver` 解析当前主网
- 调用 `Ae2DriveScanner` 生成扫描摘要
- 调用 `SorterNetworkDumpWriter` 写出 dump JSON
- 调用 `SorterFileLogger` 记录失败与 dump 结果
- 返回 `SorterDumpCommandResult`

**定位：** `/sorter me dump` 的应用层服务。

### `SorterMeCommandResult`
**职责：** 封装 `/sorter me` 命令执行结果。

**主要字段：**
- `success`
- `message`
- `plannedMoveCount`
- `requestedAmount`
- `movedAmount`

**定位：** 命令层与应用服务层之间的结构化返回对象。

### `SorterDumpCommandResult`
**职责：** 封装 `/sorter me dump` 命令执行结果。

**主要字段：**
- `success`
- `message`
- `dumpFilePath`
- `mountedCellCount`
- `uniqueItemKeyCount`

**定位：** dump 命令的结构化返回对象。

## 7. AE2 目标解析与结果模型

### `Ae2ControllerTargetResolver`
**职责：** 从命令执行上下文里解析玩家面向的 AE2 网络目标。

**主要功能：**
- 用玩家视线拾取方块
- 判断目标是否是 `ControllerBlockEntity`
- 从 controller 主节点上获取 `IGrid`
- 生成 `Ae2GridTargetResult`
- 兼容返回 `SorterMeScanResult` 形式的扫描结果摘要
- 提供 `formatBlockPos` 辅助方法

**定位：** `/sorter me` 的“网络入口定位器”。

### `Ae2GridTargetResult`
**职责：** 表示一次 AE2 网络目标解析的结果。

**主要字段含义：**
- 是否成功
- 用户提示文案
- 状态码
- 命中方块与 controller 坐标
- 是否检测到 controller
- 是否解析出 grid
- 维度 id

**定位：** 面向命令、日志、dump 的统一目标解析返回对象。

### `SorterMeScanResult`
**职责：** 表示一次 `/sorter me` 扫描层面的摘要结果。

**主要内容：**
- 成功/失败状态
- 用户提示
- drive 数量、cell 槽位数、mounted cell 数量
- 唯一 item key 数量、重复 key 数量、重复 cell 引用数量
- 网络 pivot 描述

**定位：** 比 `Ae2GridTargetResult` 更偏“扫描统计结果”的返回模型。

## 8. AE2 扫描层

### `Ae2DriveScanner`
**职责：** 扫描一个 AE2 网络中的 supported drive，并统计物品分布情况。

**主要功能：**
- 遍历 `DriveMachineAccessor.findSupportedDrives(grid)` 结果
- 遍历每个 drive 的 cell 槽位
- 统计：
  - drive 数量
  - 已扫描 cell 槽位数量
  - 已挂载 cell 数量
  - 唯一 `AEItemKey` 数量
  - 重复 item key 数量
  - 重复 cell 引用数量

**定位：** 自动整理与 dump 导出的基础扫描器。

### `Ae2DriveScanSummary`
**职责：** 承载 `Ae2DriveScanner` 的统计结果。

**定位：** 简单摘要 record，用于命令、日志、dump、分析流程之间传递扫描统计值。

### `DriveCellReference`
**职责：** 唯一标识一个 drive 内的某个 cell 槽位。

**字段：**
- `drivePos`
- `slot`

**定位：** 用于整理计划、日志、重复分布识别。

### `DriveMachineAccessor`
**职责：** 从 AE2 `IGrid` 中找到支持的 drive，并通过反射适配其 cell 访问接口。

**主要功能：**
- 支持 `ae2:drive`、`extendedae:ex_drive` 与 `appliedinsight:digital_asset_vault`
- 从 `grid.getMachineClasses()` / `grid.getMachines(...)` 中收集机器
- 校验机器是否为支持的 drive block
- 通过反射探测：
  - `getCellCount()`
  - `getOriginalCellInventory(int)`
  - `getCellInventory(int)`
- 构建内部 `DriveMachine` 包装对象
- 对 DAV 暴露 `getDeclaredZoneId()`

**内部类：** `DriveMachine`
- 封装一个 drive block entity
- 提供 `blockPos()`、`cellCount()`、`blockId()`
- 提供 `getOriginalCellInventory(slot)` 与 `getCellInventory(slot)`
- 若宿主为 DAV，则可读取声明的 `zoneId`

**定位：** AE2 / ExtendedAE / DAV 的 drive-like machine 兼容层，也是后续 `RuntimeCell` / `RuntimeZone` 的底层来源。

## 9. AE2 自动整理层

> 这部分能力的详细规划已拆分到：
> `docs/自动整理/自动合并同类-sorter.md`

### 当前重构方向

这一层接下来的正式方向已经明确为：

- 引入 `AbstractSorter`
- 细分为：
  - `MESorter`
  - `ZoneSorter`
- 最终被管理的对象是 **cell**，而不是 DAV 本身
- DAV 只是承载 cell 的宿主设备；当插入 Zone Card 后，该 DAV 内部整理应由 `ZoneSorter` 接管

### `SorterMovePlanner`
**职责：** 当前第一版“把同类物品归并到首个发现的 cell”的整理计划器。

**当前定位修正：**
- 它的主要价值是**验证并沉淀 AE2 网络内物品移动的方法**
- 它不是未来长期保留的最终 sorter 抽象
- 后续会被提炼进新的 sorter 体系，作为 consolidation 算法基础

**主要逻辑：**
- 遍历所有 drive/cell
- 对每个 `AEItemKey` 记录第一次出现的 cell 作为目标 cell
- 后续如果同类物品出现在其它 cell，则尝试模拟插入到第一个 cell
- 若可插入，则形成 `PlannedMove`
- 达到 `maxTransfers` 后提前停止
- 输出 `SorterMoveOperation`

**定位：** 当前自动整理 MVP 的核心验证器，后续会向 `AbstractSorter` 系列演进。

### `SorterMoveOperation`
**职责：** 保存整理计划，并负责执行这些计划。

**主要功能：**
- 保存 `plannedMoves`
- 保存内部可执行动作 `ExecutableMove`
- 统计总计划数量与总计划搬运量
- `execute()`：
  - 从源 storage 抽取
  - 向目标 storage 插入
  - 若插入不足则把余量返还源 storage
  - 统计成功/失败/实际搬运量

**内部类：** `ExecutableMove`
- 保存一次执行所需的源 drive、目标 drive、源 storage、目标 storage

**定位：** 计划与执行之间的桥梁对象。

### `SorterMoveExecutionResult`
**职责：** 表示执行阶段的统计结果。

**字段：**
- 尝试次数
- 完成次数
- 失败次数
- 请求搬运量
- 实际搬运量

### `PlannedMove`
**职责：** 表示一条具体的整理移动计划。

**字段：**
- `AEItemKey key`
- `amount`
- `source`
- `destination`

**定位：** 日志、执行、调试时的最小整理单元。

## 10. AE2 Dump 导出层

### `SorterNetworkDumpResult`
**职责：** 表示 dump 写出后的摘要结果。

**字段：**
- dump 文件路径
- drive 数量
- mounted cell 数量
- 唯一 item key 数量
- item occurrence 数量

### `SorterNetworkDumpWriter`
**职责：** 把当前 AE2 网络内容导出为 JSON dump。

**主要功能：**
- 遍历所有 supported drive/cell
- 输出 cell 级信息：
  - drive 坐标
  - slot
  - distinct item key 数量
  - cell 内总量
  - entries 列表
- 输出 item 聚合信息：
  - item id / mod id / display name
  - total amount
  - occurrence count
  - 是否有 components patch
  - max stack size
  - tags
  - SNBT
  - 每次出现的位置与数量
- 输出 command / target / summary / cells / items 五大块
- 写入 `dumps/appliedinsight/` 目录

**内部类/record：**
- `AggregatedItemBuilder`：构建 item 聚合信息
- `NetworkDump`：整个 dump 根对象
- `CommandDump`：命令执行上下文
- `TargetDump`：目标 controller 信息
- `SummaryDump`：网络摘要
- `CellDump` / `CellEntryDump`：cell 维度结构
- `ItemDump` / `ItemOccurrenceDump`：item 聚合结构

**定位：** 所有离线分析链路的数据源生成器。

## 11. 过滤器规则模型层（`rule.filter`）

### `FilterCombinator`
**职责：** 定义过滤组组合符。

**枚举值：**
- `AND`
- `OR`

### `FilterCombinatorDefinition`
**职责：** 面向 UI 暴露 combinator 元数据。

**主要功能：**
- 保存 `name` 与 `label`
- `defaults()` 返回默认 combinator 定义列表

### `FilterExpression`
**职责：** 过滤表达式统一父接口。

**实现者：**
- `FilterCondition`
- `FilterGroup`

### `FilterCondition`
**职责：** 表示单条原子过滤条件。

**主要功能：**
- 持有 `field` / `operator` / `value`
- 对 unary operator（`IS_TRUE` / `IS_FALSE`）自动归一化 value
- 对非 unary operator 强制要求非空值

### `FilterField`
**职责：** 定义可过滤的字段。

**枚举值：**
- `ITEM_ID`
- `MOD_ID`
- `TAG`
- `DISPLAY_NAME`
- `HAS_COMPONENTS`
- `TOTAL_AMOUNT`

### `FilterFieldDefinition`
**职责：** 面向 UI 描述一个字段的元数据。

**内容包括：**
- 名称
- 标签
- 描述
- 值类型
- editor 类型
- 支持的 operator 列表

### `FilterGroup`
**职责：** 表示树形过滤表达式中的组合节点。

**主要功能：**
- 保存 combinator 与子 rules
- `and(...)` / `or(...)` 辅助工厂方法

### `FilterMatchMode`
**职责：** 兼容旧 JSON 结构时的 matchMode 枚举。

**枚举值：**
- `ALL`
- `ANY`

### `FilterOperator`
**职责：** 定义支持的比较操作符。

**枚举值：**
- `EQUALS`
- `CONTAINS`
- `IN`
- `GREATER_OR_EQUAL`
- `LESS_OR_EQUAL`
- `IS_TRUE`
- `IS_FALSE`

### `FilterOperatorDefinition`
**职责：** 面向 UI 暴露操作符元数据。

**内容包括：**
- 名称
- 标签
- 描述
- 是否是一元操作符 `unary`

### `FilterUiMetadata`
**职责：** 前端 Query Builder 所需的完整元数据集合。

**主要功能：**
- 聚合 fields / operators / combinators
- `createDefault()` 生成默认 metadata
- 为 React 端提供统一字段、操作符、编辑器类型契约

### `FilterUiMetadataCli`
**职责：** 操作 filter UI metadata 的命令行工具。

**支持命令：**
- `write-default`
- `inspect`

**定位：** 面向前端/离线工具的 metadata 导出入口。

### `FilterUiMetadataJsonCodec`
**职责：** `FilterUiMetadata` 的 JSON 读写器。

**主要功能：**
- `load()`
- `write()`
- `toJson()`
- `fromJson()`

### `FilterValueType`
**职责：** 定义字段值类型。

**枚举值：**
- `STRING`
- `NUMBER`
- `BOOLEAN`

### `ItemFilter`
**职责：** 表示完整过滤器对象。

**主要内容：**
- id / name / description / enabled
- `root` 树形表达式

**辅助方法：**
- `allOf(...)`
- `anyOf(...)`
- `allConditions()`：展开树，收集所有原子条件

### `ItemFilterMatcher`
**职责：** 执行过滤器匹配。

**主要功能：**
- 支持整个 `ItemFilter` 匹配
- 支持 `FilterExpression` 递归匹配
- 支持 `FilterCondition` 原子匹配
- 对字符串字段支持：
  - equalsIgnoreCase
  - containsIgnoreCase
  - csv in
- 对 tag 字段做集合匹配
- 对布尔字段支持 unary 判断
- 对总量字段做数值比较

**定位：** 路由引擎的匹配执行器。

### `ItemMatchContext`
**职责：** 表示一个待匹配物品的上下文。

**字段：**
- `itemId`
- `modId`
- `displayName`
- `tags`
- `hasComponents`
- `totalAmount`

**定位：** 过滤器与路由引擎的统一输入数据模型。

### `RoutingEngineExample`

### `RoutingExplanation`

### `RoutingProfile`
**职责：** 表示完整 routing profile。

**主要内容：**

**主要功能：**

### `RoutingProfileJsonCli`

## 14. 离线分析层（`analysis`）

### `SorterDumpAnalyzer`
**职责：** 对 dump JSON 做基础统计分析。

**主要功能：**
- 使用 `JsonReader` 流式读取 dump
- 读取 summary 与 items
- 统计：
  - itemCount
  - totalAmountAcrossItems
  - componentItemCount
  - taggedItemCount
  - bulkCandidateCount
- 聚合 top items / top mods / top tags / top component items
- 输出文本分析报告

**内部结构：**
- `AnalysisResult`
- `DumpSummary`
- `ItemAggregate`
- `ModAggregate`
- `TagAggregate`

**定位：** 最基础的 dump 概览分析器。

### `SorterDumpRoutingAnalyzer`
**职责：** 用某个 routing profile 去分析 dump 中每个物品的路由结果。

**主要功能：**
- 读取 dump items
- 构造 `ItemMatchContext`
- 调用 `RoutingEngine.decide(...)`
- 统计各 decision type 计数
- 统计每个 zone 的 itemCount / totalAmount / fallbackItemCount
- 输出 fallback item 列表
- 写出文本报告

**内部结构：**
- `AnalysisResult`
- `DumpItem`
- `ZoneAggregate`
- `RoutedItem`

**定位：** profile 对真实网络数据的离线分类分析器。

### `SorterDumpRoutingSuggestionAnalyzer`
**职责：** 基于 routing analysis 的 fallback 结果，给出规则建议。

**主要功能：**
- 聚合 fallback items
- 按 mod 汇总 fallback 压力
- 选出 top fallback mods / top fallback items
- 自动生成英文建议文本：
  - 建议增加 mod-based rule
  - 建议增加 explicit item rule
- 输出 suggestion report

**内部结构：**
- `SuggestionResult`
- `ModSuggestionAggregate`

**定位：** 从“未被良好分类的物品”反推新规则候选。

### `SorterDumpProfileGenerationAnalyzer`
**职责：** 分析链路的最终组装入口，用于从 base profile + dump 生成 draft profile。

**主要功能：**
- 加载 base profile
- 调用 routing analyzer
- 调用 suggestion analyzer
- 调用 `HeuristicRoutingProfileGenerator`
- 写出 generated profile JSON
- 写出 notes.txt

**定位：** 一键式 draft profile 生成入口。

## 18. 当前类之间的主流程关系

### 16.1 Minecraft 内运行时整理流程

1. `appliedinsight` 启动并注册命令
2. 玩家执行 `/sorter me`
3. `SorterCommands` 调用 `SorterMeService`
4. `SorterMeService` 调用 `Ae2ControllerTargetResolver`
5. `Ae2DriveScanner` 扫描 drive 状态
6. 当前版本仍由 `SorterMovePlanner` 生成整理计划
7. `SorterMoveOperation.execute()` 执行移动
8. `SorterFileLogger` 写日志

> 后续会重构为：`RuntimeCell` / `RuntimeZone` + `AbstractSorter` / `MESorter` / `ZoneSorter`。

### 16.2 Minecraft 内运行时 dump 流程

1. 玩家执行 `/sorter me dump`
2. `SorterCommands` 调用 `SorterDumpService`
3. `SorterDumpService` 解析 controller 与 grid
4. `Ae2DriveScanner` 提供摘要
5. `SorterNetworkDumpWriter` 写出 dump JSON
6. `SorterFileLogger` 记录 dump 过程

### 16.3 纯 Java 路由分析流程

1. `RoutingProfileJsonCodec` 读取 profile JSON
2. `SorterDumpRoutingAnalyzer` 读取 dump JSON
3. dump item 转换成 `ItemMatchContext`
4. `RoutingEngine` 调用 `ItemFilterMatcher`
5. 输出 decision / zone aggregate / fallback items

### 16.4 规则建议与 draft 生成流程

1. `SorterDumpRoutingSuggestionAnalyzer` 汇总 fallback 结果
2. `ProfileGenerationRequest` 组装参数
3. `HeuristicRoutingProfileGenerator` 生成 zone/filter/route 候选
4. `RoutingProfileJsonCodec` 写出 generated profile
5. `SorterDumpProfileGenerationAnalyzer` 输出 notes

## 19. 当前项目的核心价值

从类设计上看，这个项目现在的核心价值不是单一“整理盘碎片”，而是：

1. **把 AE2 内部网络状态转成可导出的结构化数据**
2. **把路由规则建模成纯 Java、可解释、可序列化的对象系统**
3. **把前端 UI、JSON schema、Java matcher、分析器统一到同一套契约上**
4. **为未来更强的自动规则建议与生成预留扩展接口**

换句话说，项目已经具备三层基础设施：

- **运行时基础设施**：命令、应用服务、AE2 扫描、搬运、日志、dump
- **规则基础设施**：zone / filter / route / profile / matcher / codec
- **分析基础设施**：dump analyzer / routing analyzer / suggestion analyzer / generator

## 20. 一句话结论

Applied Energistics: Insight 当前已经不只是单纯的“盘整理小工具”或“离线分析工具”，而是一个围绕 **AE2 内部存储治理、路由配置、离线分析、前端对接、profile 自动生成，以及自定义治理型物理设备** 逐步搭建起来的平台。
