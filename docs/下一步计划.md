## 2. 未来方向：HTTP API Server + H2 数据库

> ⚠️ **本节内容为远期规划方向**，在"完善傻瓜式游戏内交互"（SorterCommandBlock GUI 完善、DAV 交互优化等）完成之后实施。

经过多轮架构讨论，项目决定引入两个重大基础设施能力，为模组提供外部访问能力和持久化存储能力。

### 2.1 动机

当前模组的所有操作都依赖游戏内交互（命令方块 GUI 或 `/sorter` 命令），且 storageDump 扫描结果以纯 JSON 文件形式存储。这带来以下限制：

1. **无外部访问**：无法通过手机/浏览器查看存储状态或触发整理操作
2. **JSON 文件局限**：纯 JSON 文件不支持查询、不支持增量更新、大文件时读写性能差
3. **无账号体系**：无法区分不同管理员的操作权限

### 2.2 HTTP API Server

**技术选型**：基于 JDK 内置 [`com.sun.net.httpserver.HttpServer`](https://docs.oracle.com/en/java/javase/21/docs/api/jdk.httpserver/com/sun/net/httpserver/HttpServer.html)（零外部依赖）

**定位**：基础设施层，与 `network/` 同级，作为模组的外部访问入口

**提供能力**：
- REST API 供前端/手机访问
- 查询存储状态、触发整理操作
- 与游戏内命令共享同一套后端服务

### 2.3 H2 嵌入式数据库

**技术选型**：[H2 Database](https://www.h2database.com/)（嵌入式模式，零外部进程依赖）

**定位**：基础设施层，与 `logging/` 同级，替代纯 JSON 文件方案

**提供能力**：
- 存储 storageDump 扫描结果
- 支持 SQL 查询（按物品、按 zone、按时间范围）
- 增量更新，避免全量重写
- 历史数据归档与趋势分析

### 2.4 认证方案

Mod 内置账号管理，不依赖外部认证服务：

| 命令 | 功能 |
|------|------|
| `/sorter api addUser <username> <password>` | 添加 API 用户 |
| `/sorter api removeUser <username>` | 删除 API 用户 |
| `/sorter api listUsers` | 列出所有 API 用户 |

**技术栈**：
- **密码存储**：bcrypt（`org.mindrot.jbcrypt` 或 JDK 内置 `MessageDigest` + salt）
- **会话认证**：JWT（`io.jsonwebtoken` 或自实现 HMAC-SHA256）
- **Token 有效期**：可配置，默认 24 小时

### 2.5 实施顺序

```
阶段 1: 完善傻瓜式游戏内交互（SorterCommandBlock GUI、DAV 交互优化等）
    ↓
阶段 2: 引入 H2 数据库（替换 JSON 文件方案）
    ↓
阶段 3: 引入 HTTP API Server（提供 REST API）
    ↓
阶段 4: 引入账号管理（bcrypt + JWT 认证）
```

### 2.6 架构影响

- **新增包路径**：`http/`（HTTP API Server 层）、`db/`（数据库层）
- **新增依赖**：H2 Database、bcrypt、JWT
- **现有变更**：`SorterStorageAnalysisService` 等 dump 服务增加 H2 写入路径
- **不改变**：六层架构、三条能力路径、纯规则层隔离原则
